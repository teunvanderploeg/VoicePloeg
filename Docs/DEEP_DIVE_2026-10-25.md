# VoicePloeg review and improvement proposal

Reviewed on 25 October 2026 against the current working tree, including the uncommitted live dictation implementation.

Implementation update: experimental live dictation was subsequently rolled back in commit `7e5a322`. The applicable upgrades are recorded in `Docs/UPGRADES_2026-10-25.md`. Findings below describe the review snapshot, including source line references from that snapshot.

The next development work should focus on reliable dictation, recovery after errors, and predictable resource use. The app already has useful separation between capture, transcription, model installation, and text output. A broad rewrite would add risk before resolving several concrete bugs.

This proposal covers first-party Swift code, the bundled Python workers and loaders, model metadata, build and release scripts, settings, tests, and documentation. The vendored Whisper CLI was checked where its behavior affects the app's integration. This is not an audit of all upstream Whisper, PyTorch, or MLX internals.

## Current behavior and validation

The coordinator owns the UI state and freezes a recording's model and language selection. Audio capture converts microphone input to 16 kHz mono samples. Normal mode transcribes after stopping. Live mode detects phrases on a separate actor, processes them in order, and stops inserting when the original editor can no longer be verified. Whisper starts a CLI process per request. Bark and Crisper retain Python workers between requests.

Several earlier backlog items are already addressed. Subprocess work and streaming model hashing run away from the main actor. Whisper downloads enforce size and SHA-256 checks. The vendor revision is pinned. Clipboard snapshots preserve multiple items and types and avoid overwriting a later user copy. A transcript is saved before normal insertion, so an insertion failure does not discard the recognized text. Live output has explicit target and cursor guards.

## Priority 1 fixes

These affect transcription correctness, the recording lifecycle, or recovery after failure.

### 1 Auto language mode currently invokes Whisper in English

[WhisperCppTranscriber.swift](/Users/teun/Code/VoicePloeg/Core/STT/WhisperCppTranscriber.swift:67) converts `auto` to `nil`. The worker then omits `-l`. The vendored [CLI defaults to `en`](/Users/teun/Code/VoicePloeg/Vendor/whisper.cpp/examples/cli/cli.cpp:84), so Auto does not request language detection, even with a multilingual model. A disposable CLI diagnostic confirmed the missing argument.

Pass `-l auto` explicitly for multilingual Auto requests. Separately fix [model capability checks](/Users/teun/Code/VoicePloeg/Core/Models/ModelManager.swift:50), which currently allow Auto with every Whisper model, including English-only weights. The CLI forces English for those weights. Existing tests explicitly accept that misleading combination and need to change.

Acceptance: a CLI contract test captures `-l auto`; English and Dutch pass their explicit language; English-only models cannot claim automatic multilingual detection. Add a Dutch audio fixture with a reference transcript to validate actual Auto behavior.

### 2 Hotkey errors can leave recording active while the UI shows an error

[Hotkey registration failure](/Users/teun/Code/VoicePloeg/App/AppCoordinator.swift:732) writes directly to the canonical recording state. The [hotkey editor](/Users/teun/Code/VoicePloeg/UI/Settings/SettingsView.swift:454) remains available during dictation. If registration fails then, `.listening` becomes `.error` while the recorder remains active. Model management becomes available, and the [recording timer](/Users/teun/Code/VoicePloeg/App/AppCoordinator.swift:640) ignores the error state instead of stopping capture. The capture buffer still has its sample cap, but the microphone engine can remain running.

A diagnostic injected registration failure during a recording and confirmed that the stop timer never called the recorder. The [hotkey service](/Users/teun/Code/VoicePloeg/Core/Hotkey/GlobalHotkeyService.swift:113) also unregisters the working shortcut before attempting its replacement.

Keep configuration errors separate from recording lifecycle transitions. Disable hotkey editing during dictation, restore the prior registration on failure, and preserve the last working preference. Make recording cleanup depend on an owned recording session as well as its displayed state. Surface failures for the fixed language shortcut and shared handler too.

Acceptance: failed shortcut changes preserve the working shortcut; errors during recording cannot enable model deletion or bypass capture cleanup; the recording limit always stops the active session.

### 3 Normal Whisper mode checks readiness after the user has spoken

[Normal recording startup](/Users/teun/Code/VoicePloeg/App/AppCoordinator.swift:471) checks installed assets for Bark and Crisper, but not Whisper. [Model resolution](/Users/teun/Code/VoicePloeg/App/AppCoordinator.swift:686) happens after capture stops and can start a download. CLI resolution happens later still. A user can record two minutes, then discover that the model is unavailable offline or that the executable is missing. There is no retry action for that captured recording.

Introduce one backend readiness check before capture. Report missing models and runtimes with the action needed to install them. Validate the Whisper executable and verify the model before accepting speech. Show preparation separately from recording. Keep a failed normal recording in memory long enough to offer retry or explicit discard, with clear ownership and cleanup.

Acceptance: a missing model, corrupt model, unavailable runtime, or missing CLI prevents capture; no model download starts implicitly after a completed recording; a transient transcription failure can be retried without recording again.

### 4 Process timeout and shutdown need stronger lifecycle handling

[SubprocessRunner](/Users/teun/Code/VoicePloeg/Core/Support/SubprocessRunner.swift:47) kills the direct process on cancellation or timeout. A diagnostic launched a shell with a child process and confirmed the child survived the timeout. Installers can spawn their own processes, so killing the parent alone does not guarantee installation work has stopped before temporary directories are removed.

[Worker shutdown](/Users/teun/Code/VoicePloeg/Core/STT/LocalSpeechWorkerClient.swift:88) sends a shutdown command, reads the response, then immediately kills a process that has not yet exited. That can interrupt Python cleanup. The actual Crisper smoke run emitted a leaked-semaphore warning at shutdown. The warning establishes a cleanup problem in this run; the precise contribution of forced termination needs a focused test.

Give launched installation work an owned process group or equivalent descendant cleanup. Await exit before deleting files it may still use. For a worker that acknowledges shutdown, allow a short bounded exit period before escalating termination. Use immediate termination for cancellation when required, with cleanup tests for that path.

Acceptance: cancellation and timeout leave no descendants; shutdown tests verify both response handling and process exit; normal worker shutdown gives Python a chance to release resources.

### 5 Preferred microphone routing changes the system default

[Input selection](/Users/teun/Code/VoicePloeg/App/AppCoordinator.swift:740) changes the macOS default input and restores it on the usual stop/error paths. [Quit](/Users/teun/Code/VoicePloeg/App/MenuBarRoot.swift:88) terminates directly without coordinated restoration. The setting also persists a numeric [AudioDeviceID](/Users/teun/Code/VoicePloeg/Core/Settings/AppSettings.swift:68), rather than a durable device UID.

Prefer input routing scoped to the app after a feasibility test with AVAudioEngine. Until then, add coordinated shutdown, restore only when the current system default is still the one VoicePloeg selected, and retain enough information to recover an interrupted switch. Persist the device UID and resolve it to the current device ID. Monitor capture configuration changes and device loss, not only the available device list.

Acceptance: quitting during recording restores the route; a user changing the system input during recording is respected; reconnecting or restarting does not select an unrelated device; device loss produces a recoverable capture outcome.

## Priority 2 reliability and performance work

### 6 Bring Crisper installation validation up to the other backends

[Crisper installed-state checks](/Users/teun/Code/VoicePloeg/Core/Models/ModelManager.swift:288) only require two files to exist. A diagnostic created a zero-byte `model.safetensors` and an invalid manifest, and the app still reported the model installed. The [installer](/Users/teun/Code/VoicePloeg/Resources/CrisperWorker/worker.py:147) pins a revision, but only checks that the weight file exists before publishing its ready marker. It does not perform Bark's explicit per-file verification and model load check. [Crisper runtime status](/Users/teun/Code/VoicePloeg/Core/STT/CrisperRuntimeManager.swift:67) likewise checks for an executable and manifest existence without decoding the manifest.

Use a shared installation manifest contract with backend-specific required files, revision, runtime version, sizes, and integrity data. Validate required tokenizer/configuration files and loadability before marking an installation ready. Keep routine UI status checks cheap and perform full verification on a worker. Preserve an existing installation until its replacement passes checks. Verify runtime health after its final placement, including any executable paths affected by moving a virtual environment.

Acceptance: malformed manifests, empty weights, missing tokenizer files, wrong revisions, and failed repairs cannot appear ready. Interrupted replacement preserves or recovers the previous usable installation.

### 7 Bound audio normalization gain and test background noise

[Normalization](/Users/teun/Code/VoicePloeg/Core/Audio/AudioCaptureService.swift:209) scales every nonconstant recording to a peak of 0.95. A diagnostic showed input at `+/-0.000001` receiving 950,000 times gain. Digital silence is handled, but low-level noise is not. This can feed amplified noise into normal transcription; the diagnostic does not establish a hallucination rate.

Use bounded gain and a measured speech/noise policy. Preserve quiet opening words and avoid a crude gate that removes them. Compare raw, capped-gain, and current audio using quiet speech, steady noise, impulses, and silence before choosing thresholds.

### 8 Improve phrase boundaries using accuracy measurements

[Live segmentation](/Users/teun/Code/VoicePloeg/Core/Audio/LivePhraseSegmenter.swift:8) uses a fixed energy threshold, 760 ms of silence, a 120 ms minimum speech count, and a forced 15-second boundary. Bark also [cuts longer recordings](/Users/teun/Code/VoicePloeg/Resources/BarkWorker/bark_worker.py:101) at low-energy points. Forced cuts have no overlap or recognition context and can divide a word. Short utterances and noisy rooms need broader coverage than the current synthetic tests.

Build an English/Dutch dictation corpus with reference transcripts, including names, code terms, short words, quiet speech, and continuous sentences. Evaluate adaptive energy detection or a local VAD. Test bounded overlap and duplicate handling only if boundary errors justify them. Keep processing order and the existing insertion guards.

### 9 Reduce synchronous Accessibility work during live dictation

[Live polling](/Users/teun/Code/VoicePloeg/Core/STT/LiveDictationSession.swift:70) validates the editor every 100 ms. Each [validation](/Users/teun/Code/VoicePloeg/Core/TextOutput/FocusedLiveTextOutputSession.swift:185) synchronously reads focus, the entire field value, and selection on the main actor. The newer implementation batches text and selection reads where supported and waits for asynchronous confirmation, but multiple AX calls can still each consume their configured 200 ms timeout. Long documents and unresponsive editors can therefore stall the menu and settings.

Measure main-thread time and field-size scaling. Use editor notifications or input invalidation where available, reduce periodic full reads, and retain a strict verification immediately before insertion. Establish one timeout budget for an operation. Move safe file operations and model-directory deletion away from the main actor as part of the same responsiveness review.

Acceptance: an unresponsive editor does not produce repeated long UI stalls, and optimized checks still permanently pause insertion after user edits or focus changes.

### 10 Measure the complete live delivery path before changing inference

The offline fixture produced the following per-phrase processing times in this review. Each phrase contains approximately 11 seconds of the same English JFK audio. These are individual observations and exclude phrase detection, editor delivery, and model loading outside the transcription request.

| Backend | First phrase | Second phrase |
| --- | ---: | ---: |
| Whisper base English q5_1 | 0.60 s | 0.60 s |
| Whisper base multilingual q5_1 | 0.60 s | 0.58 s |
| Bark Standard | 0.83 s | 0.21 s |
| Crisper medium | 3.00 s | 2.06 s |

The [clipboard transaction](/Users/teun/Code/VoicePloeg/Core/TextOutput/TextOutputController.swift:299) deliberately waits one second per paste. That wait protects delivery but serially delays each clipboard-based live phrase. Together with pause detection, it can exceed warm inference time.

Record timestamps for speech end, phrase readiness, queue entry, model readiness, inference completion, paste posting, and confirmed insertion. For verifiable live editors, investigate restoring the clipboard after confirmed delivery with a bounded fallback. Keep the existing conservative wait for editors that cannot confirm delivery. Posting an event alone is insufficient evidence that the editor has read the clipboard.

Whisper [preloading](/Users/teun/Code/VoicePloeg/Core/STT/WhisperCppTranscriber.swift:40) warms the filesystem cache; it does not retain an inference model. Benchmark a persistent helper or direct bridge only after measuring model initialization as a meaningful part of end-to-end latency. Keep any experiment behind the existing transcription interface.

### 11 Unify model preparation and runtime maintenance

[Bark maintenance](/Users/teun/Code/VoicePloeg/App/AppCoordinator.swift:404) cancels preparation before modifying the runtime, while [Crisper maintenance](/Users/teun/Code/VoicePloeg/App/AppCoordinator.swift:371) does not consistently follow that sequence. Preparation checks recording state but does not uniformly exclude runtime installation/removal. Selection changes during a recording skip preparation, and completion does not schedule the newly selected model. Preparation failures are swallowed with `try?`.

Give preparation and maintenance a common lifecycle with cancellation, completion, and a selection generation. Join obsolete preparation before modifying its assets. Schedule the current selection after recording ends, and show preparation/readiness failures separately from recording errors. Add an idle unload policy if the documented ten-minute policy is intended; no such timer exists in the current implementation.

Acceptance: language changes during setup or recording cannot load assets being removed, an old completion cannot overwrite a new selection, and an idle worker unloads according to the documented policy.

### 12 Make model selection and permission recovery easier to understand

The Default picker [admits Crisper models](/Users/teun/Code/VoicePloeg/UI/Settings/LanguageModelAssignmentsView.swift:26), while Auto requires Whisper. Selecting a valid Default for explicit languages can consequently break Auto. Download controls say "Download / Activate" even though assignment is separate. Settings expose compatibility and installed state in different places. Accessibility failure in normal mode is discovered at insertion, and permission status mainly refreshes on settings appearance or recording startup.

Represent backend capabilities explicitly and apply them in the pickers and readiness checks. Either give Auto its own compatible assignment or clearly constrain Default when Auto is selected. Rename the download action to match its behavior. Show the active model's readiness and provide direct installation and permission recovery actions. Refresh permissions when the app becomes active.

### 13 Fix shortcut labels and validate shortcuts before saving

[Key labels](/Users/teun/Code/VoicePloeg/Core/Hotkey/GlobalHotkeyService.swift:38) derive letters from numeric key codes. A diagnostic confirmed physical ANSI S, key code 1, displays as B. Use the current keyboard layout for printable keys and explicit names for special keys. Reject reserved conflicts, including the fixed language shortcut, and provide a way to cancel shortcut recording without saving a replacement.

### 14 Make transcript retention an explicit preference

[History](/Users/teun/Code/VoicePloeg/Core/Settings/AppSettings.swift:82) always persists transcript text in UserDefaults, capped at 40 items. There is no retention duration or history-off setting. Clearing history also [leaves the current transcript](/Users/teun/Code/VoicePloeg/App/AppCoordinator.swift:303) available in memory and in the menu.

Add a history retention preference and per-entry deletion. Define whether "Clear History" also clears the current transcript, and label the actions accordingly. For a larger history feature, use a dedicated store with atomic writes and clear data ownership. Encryption is a separate product choice; moving the same plain text into another file would not provide it.

## Tests and maintenance

Keep the current protocol boundaries and expand regression coverage around the actual failures. Existing tests cover coordinator startup, phrase ordering, target guards, clipboard restoration, worker cancellation, and file hashing. The gaps are in CLI argument behavior, errors that occur during another operation, real device changes, and installation recovery.

The [Xcode scheme](/Users/teun/Code/VoicePloeg/project.yml:38) has no test targets. SwiftPM uses a Swift 5.10 tools manifest while Xcode selects Swift 6. An additional Swift 6 test run passed in the disposable review copy before the later editor-confirmation changes. Keep test language mode explicit and align validation with the production build. Add an automated macOS check for build, tests, strict concurrency, Python tests, and packaging. Keep hardware/permission tests in a separate integration job or documented release gate.

[Release preflight](/Users/teun/Code/VoicePloeg/Scripts/release_preflight.sh:112) rejects literal `UNVERIFIED` Whisper hashes but does not validate all single-file entries for missing, blank, or malformed checksums. All current entries have hashes; the remaining issue is preventing bad future metadata. Add semantic catalog validation for every backend, expected sizes, unique IDs, and supported capabilities.

Retire or mark the February [improvement backlog](/Users/teun/Code/VoicePloeg/Docs/IMPROVEMENT_BACKLOG.md:1) as historical. Update [architecture documentation](/Users/teun/Code/VoicePloeg/Docs/ARCHITECTURE.md:1) for Bark and live phrase delivery, distinguish filesystem warming from retained inference state, and resolve the unimplemented idle-unload claim. Move user-facing text into `UserFacingMessage` as the relevant code changes. Split coordinator lifecycle responsibilities and the settings view into focused components after their behavior is protected by tests.

## Proposed implementation sequence

| Step | Scope | Completion criteria |
| --- | --- | --- |
| 1 | Fix Auto language and capability checks | Captured CLI arguments and a Dutch reference fixture validate the corrected behavior; incompatible Auto selections are rejected |
| 2 | Protect recording state and shortcut changes | Configuration failure cannot orphan capture or bypass the time limit; prior shortcuts survive failed replacement |
| 3 | Add backend readiness and retry | Every backend is usable before recording begins; failed normal transcription can retry retained audio |
| 4 | Fix process ownership and shutdown | Descendants exit on cancellation; acknowledged worker shutdown gets a bounded graceful exit; cleanup tests pass |
| 5 | Repair input routing lifecycle | Quit, disconnect, reconnect, and external route changes behave correctly; preferences use device UIDs |
| 6 | Unify installation and preparation | Invalid installations never appear ready; repair and model switching cannot race; idle unload behavior is explicit |
| 7 | Measure and improve audio and delivery | Reference audio compares normalization and boundaries; end-to-end timestamps identify the largest delays; optimizations preserve insertion safety |
| 8 | Finish settings, retention, and release checks | Model actions match their behavior; history controls are explicit; CI, catalog validation, and documentation match the shipped app |

Steps 1 and 2 are the best first patch. They are small enough to review closely and address confirmed correctness and lifecycle failures. Each later step should remain a separate reviewable change. Audio routing and editor compatibility need manual macOS checks in addition to unit tests.

Run the three project-required Swift checks for each behavior change, add the relevant regression tests, and run full release preflight before release. For a latency change, compare repeated runs on the same hardware and record cold load separately from warm inference. Use reference transcripts to check recognition quality. A faster JFK fixture alone is not sufficient grounds to change the default model or segmentation policy.
